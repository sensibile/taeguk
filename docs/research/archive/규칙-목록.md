# 개발 규칙 목록

작성일: 2026-10-05 · 문서 버전: 0.6

## 사용 방법

이 목록은 확정 사항과 후보를 함께 보관한다. 제안 상태의 항목은 사용자 확인 전까지 새 강제 조건으로 취급하지 않는다. 승인된 규칙도 해당 프로젝트의 실행·배포 권한을 넘지 않는다.

## 대화에서 합의한 규칙

| ID | 버전·상태 | 내용 | 근거·범위 |
|---|---|---|---|
| GOV-001 | 1.0 · 승인 | 에이전트는 승인된 규칙을 작업 권한 내에서 자율 적용한다 | 2026-10-05 사용자 발언: “규칙의 적용은 에이전트가 자유롭게 사용하고” |
| GOV-002 | 1.0 · 승인 | 규칙의 추가·수정·폐기 및 예외 허용은 사용자 확인을 받는다 | 같은 발언: “규칙의 변경은 사용자 확인으로 하면 되겠다”. 추가·폐기·예외는 기준을 실질적으로 바꾸는 행위로 해석 |

승인 근거는 이 대화이며 외부 승인 시스템이나 별도 승인 기록은 아직 없다. 세부 규칙에 대한 승인을 추정하지 않는다.

| DEV-002 | 수정의 영향·복구 범위와 묶음 크기 제한 | 하나의 의도, 영향 범위, 독립 검증·복구 가능성 확인. 충돌·상호작용·추측성 확장 위험과 검토·검증·배포 고정 비용 비교 | 줄 수만으로 안전성을 판단하지 않음. 무조건 작은 PR이나 큰 일괄 정리를 정답으로 삼지 않음 |

| TID-002 | 구조 변경과 동작 변경의 의도 구분 | 변경 묶음별 의도, 보존할 동작, 검사 결과를 분리해 검토 가능하게 구성 | 모든 한 줄 변경의 별도 PR을 의무화하지 않음. 저장소 정책 준수 |
| TID-004 | 되돌릴 수 있는 정리인지 확인 | 코드 복구 경로와 데이터·외부 부수 효과, 의존 관계 확인 | Git 되돌리기만으로 운영 효과까지 복구된다고 가정하지 않음 |
| VER-001 | 기능과 구조를 함께 보존 | 사용자 시나리오 검사 및 관련 구조 검사 | 구조 검사 통과는 기능 보장의 대체가 아님 |
| VER-002 | 여러 조건의 상호작용 보호 | 변경이 영향을 주는 연동·전체 흐름 검사 | 모든 조합을 검사할 수 없으므로 선택 근거와 미검증 범위를 기록 |
| STR-001 | 기존 부채의 점진적 개선 | 기존 위반 기준선과 새 위반, 해소된 위반을 구분 | 기준선이 기존 위험의 안전 판정이나 자동 면제는 아님 |
| SEL-001 | 가치 없는 변경 방지 | 발견 근거, 실제 영향, 예상 개선, 위험을 비교 | 후보 발견만으로 수정하지 않음. 근거 부족 시 보류 |
| SEL-002 | 변경이 잦고 복잡한 부분부터 조사 | 분석 기간·대상 커밋·변경 빈도·규모를 기록하고 실제 코드와 문제 근거 확인 | 핫스팟 순위는 조사 순서이며 자동 수정 명령이 아님 |
| SEL-003 | 이력과 측정의 왜곡 방지 | 파일 이동·이름 변경, 생성물, 일괄 포맷 변경, 커밋 분할·병합 등 분석 조건 기록 | 이력이 부족하면 위험이 낮다고 판정하지 않고 근거 부족으로 표시 |
| SEL-004 | 조사 범위를 작은 수정 후보로 축소 | 파일 수준 후보에서 관련 함수·동작·변경 이력까지 확인 | 큰 파일 전체의 재작성으로 바로 확대하지 않음 |
| SEL-005 | 예상 밖 동시 변경 관계 조사 | 함께 바뀐 커밋과 실제 코드 관계 확인. 테스트와 제품 코드 함께 조사 | 동시 변경은 결함의 증명이 아님. 정상적인 계약·테스트 관계와 구분 |

| REL-002 | 검사한 산출물과 배포물의 동일성 보존 | 커밋·빌드 ID·산출물 해시와 단계별 검사 연결. 환경별 설정은 별도 식별 | 같은 소스라도 재빌드 결과에 이전 검사 결과를 자동 승계하지 않음 |
| REL-003 | 검증한 배포 절차 재사용 | 환경별 설정과 공통 배포 절차를 구분하고 실제 환경 차이 기록 | 테스트 환경 통과를 운영 환경의 완전한 보장으로 해석하지 않음 |
| REL-004 | 실패한 후보의 배포 진행 차단 | 필수 단계의 성공·실패·미실행·판정불가 상태 확인 | 반복 실행으로 우연히 통과한 결과만 남기거나 검사를 우회하지 않음 |
| REL-005 | 배포 후 실제 사용 가능 여부 확인 | 배포 버전, 기동·의존 서비스 상태, 핵심 사용자 시나리오와 합의된 관측 결과 | 명령 성공·프로세스 생존만으로 출시 검증 완료 판정하지 않음 |
| REL-006 | 복구 가능성을 배포 전에 확인 | 이전 정상 산출물·설정, 데이터 호환성, 외부 연동, 복구 절차와 연습 결과 | 이전 앱 배포와 데이터 복원은 다름. 복원 시 신규 데이터 손실 가능성 명시 |
| REL-007 | 배포와 사용자 공개 권한 구분 | 대상 환경·사용자 범위·전환 조건·자동 실행 허용 범위 기록 | 테스트 통과가 배포 권한 부여를 뜻하지 않음. 긴급 수정도 임의 우회 금지 |
| GOV-003 | 필수 검사 생략 방지 | 필수 규칙 실행 결과, 조건부 규칙 적용·미적용 이유 | 규칙 선택의 자율성을 임의 생략 권한으로 해석하지 않음 |
| GOV-004 | 명세의 의미 보존과 형식적 통과 방지 | 승인된 기대 결과와 실행 검사의 판정 항목 대응 확인. 제품 수정과 규칙 개정의 근거·승인·결과 구분 | 자동화 곤란을 이유로 기대값·검사 범위를 완화하거나 검사를 삭제해 자체 통과 처리하지 않음. 기준 변경은 사용자 확인 필요 |
| GOV-005 | 무한 수정·정리·재시도 방지 | 작업 범위·시간·비용·재시도 한도를 사전 설정. 현재 방해 요인 해소와 검증 완료 후 정리를 끝내고 추가 정리의 이득·비용 평가 | 추가 후보는 별도 기록. 범위·한도 초과 시 재평가하고 상반된 변환 반복 방지. 공통 임계값은 없으며 프로젝트별 합의 필요 |

각 후보를 승인할 때는 [규칙 관리](규칙-관리.md)의 항목에 따라 범위, 판정 방법, 예외, 재검토 조건을 구체화한다. 이 표만으로 자동 실행 가능한 검수 규칙이 완성된 것은 아니다.

## 중복 통합 대응표

이번 통합은 제안 문서의 편집 정리다. 승인 규칙 GOV-001·002는 그대로이며, 통합된 후보도 제안 상태를 유지한다. 아래 이전 ID는 추적용 별칭이며 별도의 검사나 승인된 대체 버전을 뜻하지 않는다.

| 이전 ID | 현재 ID | 통합한 내용 |
|---|---|---|
| REQ-005 | GOV-004 | 자동화 시 기대 결과 보존과 기준 변경 통제 |
| SEL-006 | DEV-001 | 보존 검사와 실제 개선 증거의 구분 |
| TID-003 | DEV-002 | 작은 변경의 영향과 묶음 처리 비용 |
| TID-005 | GOV-005 | 정리 종료와 작업·재시도 한도 |

REQ-003(전체 목표)과 VER-002(연동·상호작용), REQ-006(검사 추적)과 REL-001(실제 전달 추적), TID-004(수정 가역성)와 REL-006(배포 복구)은 관련되지만 적용 시점과 판정 대상이 달라 유지한다. 같은 증거가 여러 규칙을 충족하면 연결해 참조할 수 있으며, ID가 다르다는 이유만으로 동일 검사를 반복한다는 뜻은 아니다.

서적별 출처·해석·기록 양식은 [서적 검토](서적-검토.md)에 있다.

## 아직 결정하지 않은 사항

- 첫 적용 프로젝트와 실제 작업
- 필수·조건부 규칙의 구체적 분류와 실행 도구
- 성능, 복잡도, 작업 크기, 재시도에 대한 수치 기준
- 배포 대상, 자동 배포 허용 범위, 관측 기간, 복구 절차
- 승인 기록의 저장 방식과 변경 이력 관리 도구
- 스킬 구성, 에이전트 분담, 스케줄과 실행 권한

## 변경 이력

- 0.1: 개발 방향, 규칙 관리 원칙, 첫 규칙 후보와 서적 검토 계획을 기록.
- 0.2: Software Design X-Rays 선택 절 검토와 SEL-002~006 후보, 후보 기록 양식을 추가. 승인 규칙과 변경 권한은 그대로 유지. 새 후보는 모두 미승인.
- 0.3: Specification by Example 선택 부분 검토, REQ-001~006 후보와 수용 사례 양식 추가. 승인 규칙은 변경하지 않음.
- 0.4: Tidy First? 16·18·19·21·28장 검토와 TID-001~005 후보, 시점·종료 판단 추가. 승인 규칙과 리뷰·배포 권한은 변경하지 않음.
- 0.5: Continuous Delivery 5·10장 선택 부분 검토, REL-002~007 후보와 배포 기록 양식 추가. 자동 배포·복구 권한이나 승인 규칙은 변경하지 않음.
- 0.6: 중복 제안 네 쌍을 통합하고 이전 ID 대응표 유지. 서적 기록을 별도 문서로 분리. 승인 상태와 실행 권한은 변경하지 않음.
