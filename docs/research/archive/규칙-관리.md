# 규칙 관리와 진화

작성일: 2026-10-05 · 문서 버전: 0.1

## 합의된 권한 원칙

에이전트는 승인된 규칙과 권한 범위 안에서 자율적으로 작업한다. 규칙 변경이 필요하면 근거·변경안·영향을 제시하고 사용자 확인을 받는다. 확인 전에는 기존 규칙을 유지한다.

규칙 적용에 대한 자율성은 규칙을 우회하거나 예외를 임의로 만드는 권한이 아니다. 문서 작성 요청이나 개정안 검토 요청을 개별 규칙의 승인으로 간주하지 않는다.

## 상태 관리 초안

| 상태 | 의미 |
|---|---|
| 제안 | 책이나 논의에서 얻은 후보. 실행 기준으로 승인되지 않음 |
| 승인 | 사용자가 적용 내용과 범위를 확인한 규칙 |
| 대체됨 | 승인된 새 버전으로 교체됨. 이전 기록은 보존 |
| 폐기 | 사용자 확인으로 적용 종료 |

서적 근거와 승인 상태는 별개다. 책의 주장, 에이전트의 해석, 사용자의 합의를 각각 표시한다. 필수 규칙은 항상 적용하고, 조건부 규칙은 명시된 조건에 따라 선택하는 방식을 제안한다. 이 적용 분류의 세부 운영은 아직 검토 중이다.

## 규칙에 기록할 항목

- 식별자, 버전, 상태
- 보호 목적과 적용 범위
- 적용 조건 및 필수·조건부 여부
- 판정 방법, 필요한 증거, 알려진 한계
- 허용되는 수정과 중단·예외 조건
- 출처와 해석 근거
- 재검토 조건, 승인 기록, 적용 시점

승인 기록에는 사용자가 확인한 정확한 내용과 범위를 남긴다. 이 문서의 0.1은 문서 버전이며, 제안 상태 규칙의 승인을 뜻하지 않는다.

## 규칙 진화의 검토 신호

| 신호 | 확인할 근거 | 검토할 변경 |
|---|---|---|
| 통과 후 실제 문제 발생 | 재현 사례와 놓친 조건 | 추가·강화 |
| 적합한 변경을 반복 차단 | 정상 사례와 보호 목적의 불일치 | 범위·판정 수정 |
| 요구사항·환경 변화 | 기존 전제와 새 계약의 차이 | 개정 |
| 규칙 간 충돌 | 동시에 충족하지 못하는 구체적 사례 | 우선순위·예외 |
| 지표만 개선되고 실제 결과 악화 | 지표와 결과 비교 | 지표·검증 교체 |
| 중복 또는 목적 소멸 | 보장 범위 비교와 보호 대상 변화 | 통합·폐기 |

이 신호는 검토를 시작할 근거이며 자동 변경의 허가는 아니다. 신호의 빈도나 수치 임계값은 아직 정하지 않았다.

## 개정 절차 초안

1. 현재 규칙의 목적과 문제 사례를 기록한다.
2. 변경 전후의 판정 차이와 영향 범위를 명시한다.
3. 기존 실패 사례와 정상 사례에 새 규칙을 시험한다. 검증하지 못한 부분은 미확인으로 남긴다.
4. 새로 탐지하는 문제와 더 이상 탐지하지 못하는 문제, 비용을 비교한다.
5. 사용자가 변경안을 확인한 뒤 새 버전과 적용 시점을 확정한다.
6. 진행 중인 작업에 미치는 영향을 확인하고 필요한 검사를 다시 실행한다.

사용자 확인은 모든 실질적인 규칙 추가·수정·폐기와 예외에 필요하다. 기준을 강화하는 경우에도 자동 승인하지 않는다. 확인이 없으면 기존 규칙을 유지한다.

## 제품 수정과 규칙 개정의 분리

진행 중인 수정이 실패하면 먼저 제품 문제인지 검사 문제인지 조사한다. 검사 오류가 의심되어도 에이전트가 검사나 임계값을 바꾸고 같은 작업을 즉시 통과시키지 않는다. 개정안과 비교 결과를 제시해 사용자 확인을 받은 뒤 재검증한다.

진행 중인 작업은 적용한 규칙 버전을 기록한다. 새 규칙이 승인되면 기존 작업의 처리 방침도 정하며, 오래된 통과 결과를 새 규칙의 통과 결과로 재사용하지 않는다.
