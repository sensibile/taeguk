정리부터 할까?

다음 변경을 쉽게 만드는 만큼, 작게 정리한다.

Kent Beck · O’Reilly · 원문 확인 2026년 10월 5일

한국어 노트실험 기록 양식원서

공부하는 방법

핵심 요지를 읽고 질문에 먼저 답하세요. 자기 코드의 사례로 설명할 수 있으면 이해 표시를 하세요. 한 번에 하나만 실험하고 실제 효과를 기록하세요.

각 카드의 첫 문단은 책의 요지입니다. 질문과 해설은 학습용으로 별도 작성했습니다.

확인 범위

2026년 10월 5일 로그인된 O’Reilly 브라우저에서 추천사와 1~33장 본문을 확인했다. 머리말·도입부·각 부의 도입·부록·색인은 정리 범위에 포함하지 않았다. 그림은 재현하지 않았다. 장별 요지는 짧은 한국어 재구성이며 전체 번역본이 아니다. 복습 질문·답·학습 순서·예제·실험 양식은 별도로 작성했다.

시점을 판단하는 네 가지 선택

먼저: 지금의 이해나 다음 변경을 쉽게 만드는 작은 정리가 보일 때.

직후: 변경하면서 얻은 맥락을 활용하는 편이 다음에 다시 시작하는 것보다 유리할 때.

나중: 당장 이익은 작지만 별도 시간에 작은 단위로 진행할 가치가 있을 때.

하지 않기: 향후 변경이나 학습에서 기대하는 이익이 없을 때.

6회차 학습 순서

회차당 20~40분을 출발점으로 삼는 학습용 제안입니다. 코드를 바꾸는 실험은 별도 시간에 진행해도 됩니다.

  1. 1회차 · 흐름과 이름1~10장

    실제 함수 하나에서 이해를 방해하는 조건이나 이름을 찾는다. 다음에 필요한 변경을 한 문장으로 적는다.

  2. 2회차 · 경계와 설명11~15장

    분리하면 좋은 부분과 모으면 좋은 부분을 각각 찾아 이유를 적는다.

  3. 3회차 · 변경 단위16~20장

    최근 변경 하나를 구조 변경과 동작 변경으로 분류한다. 검토자가 확인할 차이를 설명한다.

  4. 4회차 · 정리 시점21장

    현재 작업에 먼저·직후·나중·하지 않기 중 하나를 선택하고 선택이 바뀔 조건을 적는다.

  5. 5회차 · 가치와 복구22~28장

    현재 이익과 미래 선택을 구분한다. 기대한 이익의 가정과 되돌리는 방법을 적는다.

  6. 6회차 · 변경의 전파29~33장

    변경 하나가 전파되는 요소를 나열하고 최소 정리 한 가지를 실험한다.

def fee_before(weight, remote):
    if weight > 0:
        if weight <= 20:
            fee = 3000 + weight * 200
            if remote:
                fee += 4000
            return fee
    return None


def fee_after(weight, remote):
    if weight <= 0:
        return None
    if weight > 20:
        return None

    base_fee = 3000
    per_kg_fee = 200
    remote_fee = 4000
    shipping_fee = base_fee + weight * per_kg_fee
    if remote:
        shipping_fee += remote_fee
    return shipping_fee


def notify_before(active, events):

        events.append("notify")
    events.append("audit")

        return

    events.append("audit")


def notify_after(active, events):
    # The audit event is required for both active and inactive users.
    if active:
        events.append("notify")
    events.append("audit")
