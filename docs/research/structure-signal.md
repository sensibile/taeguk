# 구조 개선 시그널 연구

이 문서는 연구 과제이며 현행 규칙이 아니다. 2026-10-29 BOSS가 "구조개선은 시그널이 나타날 때가 맞을 거 같아. 시그널 측정에 대해서는 연구가 필요해 보이고"라고 했다. 측정 방법이나 기준값을 정하면 BOSS 확인을 거쳐 규칙 개정안(GOV-002)으로 올린다.

## 질문

구조 개선이 필요하다는 것을 무엇으로 알 수 있는가. DEV-002는 실제 요구나 반복 변경이 이미 검증된 영역까지 수정하게 만드는 관계를 구조 개선 시그널로 본다. 읽기 난이도, 파일 길이, 가상의 미래 요구는 근거가 아니다. 이 관계를 사람의 판단 없이 관측할 방법이 아직 없다.

## 후보 시그널

| 후보 | 관측 방법 | 확인할 타당성 위협 |
|---|---|---|
| 동반 수정 | Git 이력에서 서로 다른 책임의 파일이 같은 커밋이나 PR에서 반복해서 함께 바뀐 횟수 | 의도된 동반 수정(테스트와 구현, 문서와 코드)과 구분해야 한다. squash 머지라 PR 단위로만 보인다 |
| 검증된 영역 재수정 | 새 요구를 다룬 PR이 이전에 PASS 증거가 있던 영역의 코드를 바꾼 경우 | 결함 수정이나 계약 변경으로 인한 정당한 수정과 구분해야 한다 |
| 영향 재검증 범위 | 한 요구의 변경으로 다시 실행해야 했던 검사 수와 영역 | 검사 선택이 보수적이면 범위가 부풀려진다 |
| 리뷰 지적 반복 | 같은 위치나 경계에 대한 지적이 여러 PR에서 되풀이됨(VER-005 상향과 별개) | 리뷰 모델의 성향이 반복을 만들 수 있다 |
| 정리 후보 누적 | 데일리 정리가 같은 영역에서 구조 개선 후보를 반복 보고함 | 정리 절차 자체가 같은 영역만 보게 될 수 있다 |

MET-001에 따라 각 후보는 측정 대상과 판단 목적의 연결, 데이터 출처, 오탐과 미탐 사례를 먼저 확인한다. 수치 기준은 실제 이력으로 검증하기 전에는 두지 않는다.

## 확정 전 운영

측정 방법이 정해지기 전에는 작업 리뷰, 데일리 정리, 일반 작업에서 `taeguk_structure_reviewer`가 DEV-002 근거를 관측하면 BOSS에게 보고한다. 보고에는 근거가 된 커밋이나 PR, 변하는 부분과 보존할 계약, 현상 유지·책임 이동·좁은 계약 대안을 담는다. 착수는 BOSS 승인 뒤다.
