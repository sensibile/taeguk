# 검증 흐름의 불필요한 반복 보완

2026-10-11 Veloce 재고 예약 실험을 검토했다. 기능·수용 기준·모델 구성은 유지하고 실행 충돌, 결과 전달 대기, 재검증 인계의 반복을 보완했다. 단계별 시간·토큰을 계측하지 않았으므로 절감 비율이나 가장 큰 병목을 수치로 단정하지 않는다.

## 확인한 반복과 조치

| 관찰 | 필요한 부분 / 불필요한 부분 | 조치 |
| --- | --- | --- |
| session handle을 잃고 mix test가 겹쳐 fixture 실패 후 다시 실행 | 오염된 결과를 직렬 재검증하는 것은 필요. 실행 중 명령의 중복 시작은 불필요 | PID/session·자원 소유자 기록, handle로 종료 확인. 협조적 공유 자원 실행기 추가 |
| 도구 실행은 끝났지만 최종 보고서가 작성되는 동안 결과와 DB 인계 대기 | mixed 판단은 실제 근거가 필요. 긴 설명 완성 전까지 실행 자원을 잡거나 결과를 숨길 필요는 없음 | 완료된 ID별 결과를 즉시 전달하고 실행이 끝나면 소유권 반환. source 검토는 먼저, 통합판정은 근거 도착 뒤 |
| 여러 수정 단계마다 설계·계획·원시 근거·보고서 인계가 커짐 | 대상 버전과 이전 실패 보존은 필요. 매번 전체 내용을 복제할 필요는 없음 | 한 현재 판정 표와 버전별 raw 유지. diff·영향 ID·새 근거·재사용 이유·미결 항목만 인계 |
| 변경 없는 상태를 짧게 반복 조회 | meaningful change/완료 확인은 필요. 같은 상태를 반복 읽는 것은 불필요 | 실행 handle 보존, 도구의 bounded wait 사용, 변화 없는 poll로 재실행하지 않음 |
| 시각 출처 표현 오류를 마지막에 문서만 정정 | 근거 정정은 필요. 제품 코드가 안 바뀌었는데 제품 검사를 다시 할 필요는 없음 | 설명 변경은 설명 검토와 hash 갱신으로 제한 |

화면 누락과 실제 동시성 결함을 발견한 뒤의 수정·재검증, 정확한 equality를 확인하기 위한 새로운 관측 방법, 사용자와 약속한 공통 외부 benchmark·HTTP·legacy 검사는 이번에 제거할 대상으로 분류하지 않았다. 실제 이전 실행에서도 일부 변경 없는 근거는 재사용했으므로 모든 검사를 반복했다고 주장하지 않는다.

## 적용 위치

실행·재검증 절차의 원본은 [재검증 참고](../codex/skills/taeguk-plan-cross-verification/references/reverification.md)다. coordinator/tool verifier/LLM reviewer 및 구현·검증 계획 스킬은 그 절차를 참조한다. 기존 역할의 모델과 추론 설정은 유지했다. 승인된 규칙 ID·버전·합격 기준·권한은 변경하지 않았다.

[Python 실행기](../codex/skills/taeguk-plan-cross-verification/scripts/run_exclusive.py)는 같은 lock을 쓰는 foreground 명령의 중복을 차단한다. 자식 종료 코드 보존, INT/TERM 전달, wrapper 강제 종료 시 직접 자식의 lock 상속을 지원한다. symlink/특수 lock 파일을 거절하고 lock inode를 지우지 않는다. 권한 부여 장치나 전역 프로세스 감시는 아니며 사용하지 않은 명령, 다른 lock 이름, 상속 FD를 닫는 프로그램, background/daemon에 대한 보장은 없다. macOS/Linux 대상으로 두며 새 런타임 의존성은 없다.

## 검증과 한계

- 실행기의 실제 subprocess 검사 7개: 중복 명령 미실행, 다른 자원 허용, 실패 exit와 lock 반환, 없는 명령, TERM 전달, 강제 종료 후 자식 lock 유지, symlink 거절.
- 기존 검사 포함 Python 26개, Rust 15개, Elixir 3개 및 포맷·규칙 구조 검사 통과.
- 변경 스킬 2개 validator와 역할 TOML 구문 검사 통과. 문서 링크·포맷·diff 검사 수행.
- 코드/보안 관점에서 shell 없이 argv 실행, 시작 전 lock 획득, 소유 자식 group에만 신호 전달, 미관리 파일 변경 없음, 협조적 잠금의 한계를 직접 검토했다. 별도 독립 에이전트 리뷰나 보안 스캔은 수행하지 않았다.

초기 실행기 테스트의 cleanup은 이미 종료시킨 자식 group에 두 번 신호를 보내 실패했다. 중복 cleanup 호출을 없앤 뒤 해당 subprocess 검사와 전체 회귀를 통과했다. 제품 결함이나 검증 성공으로 덮어쓰지 않는다.

지침이 실제 다음 과제에서 시간·토큰을 줄였는지는 아직 미확인이다. 도구 동작은 실행으로 확인했지만 지침 준수와 효율 개선은 다음 작업에서 실행 횟수·오염 재시도·결과 도착과 보고서 완료 사이 대기를 관찰해야 한다. 이번 요청에는 새로운 Veloce 과제 전체 재실행을 넣지 않았다.
