# taeguk-init

Install or update the Taeguk bundle in the current project. Address the user as BOSS and explain in Korean. The installer source is `{{SOURCE}}`.

1. Resolve the project root with `git rev-parse --show-toplevel`. Outside a Git repository, ask BOSS which directory to use.
2. Preview with `python3 {{INSTALLER}} project --root <root> --agent {{AGENT}}`, keeping the installer argument exactly as written and passing `<root>` as {{QUOTING}}. Use other comma-separated agents (`codex`, `claude`) only when BOSS names them, including in the command arguments. Show the planned components, file count, `installer_version` (the source being installed), `installed_versions` (what the project's receipts recorded before this run) and any warning.
3. Apply only after BOSS approves that preview. Applying changes repository files, so following DEV-003 first create a dedicated worktree and task branch from the verified base (the project's worktree convention overrides the defaults), unless BOSS says to apply in the current checkout. If the current checkout has uncommitted Taeguk files or receipts, a new worktree will not contain them; report this and ask BOSS how to proceed. Rerun the preview there with `--root` set to the worktree and confirm it matches the approved one; if it differs, show the difference and get BOSS approval again before applying, then rerun with `--apply`, then with `--check`. Report the actual results, the branch and the worktree path.
4. Installed files under `.taeguk/`, `.claude/`, `.agents/` and `.codex/` are meant to be committed so the team shares the same version. Do not commit unless BOSS asks.
5. Offer, but do not perform without approval, one line in the project's AGENTS.md or CLAUDE.md, made in the same worktree as step 3 (or the current checkout only if BOSS chose that in step 3): "Read `.taeguk/rules/index.md` before planning and apply Taeguk rules to explicitly assigned workflows; apply DEV-003 (dedicated worktree, `.taeguk/rules/development.md`) to all repository edits." When the project already has the older Taeguk line, offer to replace it, and replace it only after BOSS approves. Each installed agent must reach the line: Codex reads AGENTS.md and Claude Code reads CLAUDE.md, so when both are installed and CLAUDE.md does not already import AGENTS.md (`@AGENTS.md`), offer the line for both files. Never overwrite other existing instructions. Tell BOSS that without such a line, agents doing ordinary development outside Taeguk skills may not read DEV-003.
6. When the Codex bundle was installed, tell BOSS that Codex loads the project `.codex/agents` roles only when the project root itself is trusted (check the path where BOSS will run Codex, normally the main checkout, not a temporary install worktree) in `~/.codex/config.toml`; a trusted parent directory was not enough in codex-cli 0.164.0. Check whether that exact path is listed with `trust_level = "trusted"`; if it is missing or has another trust level, ask BOSS to trust it by opening Codex in that folder or adding it to the config. Do not edit the Codex config yourself.
7. If `shadowed_by_user_skills` appears, explain that user-level skills with the same name override the project copy in Claude Code and appear twice in Codex, and point to `taeguk_install.py migrate` and the legacy uninstall in `{{SOURCE}}/docs/installation.md`.

Rerunning the same command updates the project. Locally modified managed files block updates and removal; resolve them with BOSS instead of deleting. `--uninstall` removes only files recorded in the receipts.
